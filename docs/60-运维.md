## 2. 部署

```bash
./deploy-home-server.sh           # 全流程
./deploy-home-server.sh sync      # 只 rsync
./deploy-home-server.sh status    # 容器状态
./deploy-home-server.sh logs      # 跟日志
```

全流程五步，任一步失败即中止、线上保持旧版本：

1. `sync_source`：`rsync -ai --delete` 源码 → `/opt/allin-one`，打印变更清单。
2. `pick_registry`：依次探测 `docker.1ms.run/`、`docker.m.daocloud.io/`、Docker Hub 直连，拉三个基础镜像（`node:22-alpine`、`docker:cli`、`python:3.11-slim`）全部在 `PULL_TIMEOUT`（120s）内成功的第一个即采用；`REGISTRY=` 指定则跳过探测。
3. `build_image`：构建 `allin-one:home-server`（前端 Vite 产物打进镜像）。
4. `run_migrations`：用**新镜像**起一次性容器跑 `alembic upgrade head`，失败则中止，容器未切换。因此迁移必须对旧代码向后兼容（加表 / 加列 / 加索引），破坏性变更拆两次发布。
5. `up -d` 后 `wait_healthy` 等容器 healthy（90s 上限），再 `curl $HEALTH_URL`（默认 `http://192.168.1.103:8000/health`），最后用源码 `index.html` 里引用的 hash 反查镜像内前端产物与仓库一致。

**回滚**：部署前 `docker tag allin-one:home-server allin-one:backup-<date>`；回滚 = retag 回来 + `docker compose -f /opt/allin-one/docker-compose.home-server.yml up -d`。数据库迁移不回滚。

**全新环境初始化顺序**：起 Postgres → `alembic upgrade head` → 起应用与 worker。应用启动期的 `create_all` 会先建表，之后 alembic 报 DuplicateTable，需 `alembic stamp`。

**漂移**：生产目录曾被直接修改未回流。部署前 `diff -rq /root/workspace/the-one/allin-one/backend /opt/allin-one/backend`；the-one `/health-check` 的脚本层也做"部署 vs repo 漂移"检查。

## 3. 运行

**容器**（`docker compose -f /opt/allin-one/docker-compose.home-server.yml <cmd>`，全部 `restart: unless-stopped`，日志轮转 10MB × 3）：

| 容器 | 职责 | 健康检查 |
|---|---|---|
| `allin-one` | FastAPI + 静态前端，:8000 | 30s 一次 `GET /health`，start_period 40s |
| `allin-worker-pipeline` | Procrastinate worker，`pipeline` 队列，并发 4 | `SELECT 1` |
| `allin-worker-scheduled` | Procrastinate worker，`scheduled` 队列，并发 2；periodic 任务在这里触发 | `SELECT 1` |
| `allin-mcp` | MCP HTTP，:8001，只挂 `.env` | — |
| `allin-postgres` | PostgreSQL 17，`TZ=UTC`，库 / 用户 `allinone` | — |
| `allin-rsshub` | 非标准平台 feed 生成 | — |
| `allin-browserless` | 无头 Chromium，供 RSSHub puppeteer 路由与 L3 抓取 | — |

单个容器重启：`docker compose -f … restart allin-worker-scheduled`。改了代码不能只 restart，代码在镜像里，要走部署。

**periodic 任务**（`backend/app/tasks/scheduled_tasks.py`，cron 为 UTC，由 scheduled worker 触发）：

| 任务 | cron | 说明 |
|---|---|---|
| `check_and_collect_sources` | 每 1 分钟 | 选 `is_active AND schedule_enabled AND next_collection_at <= now` 的源入队采集 |
| `auto_sync_sources` | 每 10 分钟 | 按注册表 `auto_sync_minutes` 到期发起内置同步（目前只有 Emby，30 分钟） |
| `cleanup_scheduler` | 每小时 | 到 `cleanup_content_time`（03:00）跑内容清理，到 `cleanup_records_time`（03:30）跑记录清理；上次内容清理 2026-09-23 |
| `analyze_source_periodicity` | 20:00 UTC（04:00 CST） | 采集型源的发布周期分析 |
| `cleanup_job_queue` | 19:20 UTC（03:20 CST） | 删 7 天前结束的作业，回收心跳丢失超 1 小时的僵死作业 |
| `trigger_daily_report` / `trigger_weekly_report` | 已注释停用（2026-09-20） | 列入 `system_health._RETIRED_TASKS`，历史失败不计入总评 |

**保留参数**（`system_settings`）：内容保留 `default_retention_days` 未设，代码默认 30 天，`source_configs.retention_days` 可按源覆盖（0 = 永久）；采集记录保留 90 天、每源至少留 10 条；调度间隔 300s–86400s。

**systemd**：`allin-one-backup.timer`（每日 03:30）已安装、**disabled**；无其他单元。

## 4. 数据库

- 连接：容器内 `DATABASE_URL` 指向 `postgres` 服务；连接池 `DB_POOL_SIZE` 10 / `DB_MAX_OVERFLOW` 5，各容器独立。
- 迁移：`alembic upgrade head`，当前 head `0028_film_countries_iso`；生成 `alembic revision --autogenerate -m …` 后跑 `scripts/verify/drift/check.sh --write` 刷新 `system_design.md` 表结构段。
- 直连：`docker exec allin-postgres psql -U allinone -d allinone`。
- 在生产库上验证改动：`pg_dump` 快照 → 临时 `postgres:17-alpine` 容器（等日志出现第二次 "ready to accept connections"，`pg_isready` 会在 initdb 后的短暂启动期提前返回真）→ 用 `allin-one:home-server` 镜像挂载工作区跑 alembic / uvicorn / 脚本；镜像里没有 curl，从宿主机按容器 IP 访问。
- 时间：应用表 naive UTC（`app.core.time.utcnow`）；procrastinate 表是 timestamptz，`system_health.py` 里 `_aware` / `_naive_utc` 换算，别处一律 naive UTC。

## 5. 备份与恢复

```bash
scripts/backup-home-server.sh backup      # pg_dump -Fc（容器内）+ data/（排 logs）+ .env + compose → 一个 restic 快照，随后 forget --prune
scripts/backup-home-server.sh snapshots
scripts/backup-home-server.sh check       # 周日备份时自动跑一次
scripts/backup-home-server.sh restore-db latest /tmp/restore
```

| 项 | 值 |
|---|---|
| 仓库 | `/mnt/sda2/backup/restic-allin-one`（数据盘，与根盘不同物理盘；路由器镜像同盘） |
| 密码 | `/opt/allin-one/.restic-password`，0600，不进仓库；丢失即快照不可读，需另存 |
| 保留 | daily 30 / weekly 8 / monthly 12 |
| 心跳 | 成功写 `/var/backups/allin-one/last-success`（UTC ISO）；dump 副本留在 `/var/backups/allin-one/allinone.dump` |
| 现状 | 快照 1 份（2026-09-23 19:17，85.6MiB）；timer 停用，手动运行 |

恢复库：`docker exec -i allin-postgres pg_restore -U allinone -d allinone --clean --if-exists < <dump>`（覆盖）。整机恢复：`restic restore latest --target / --include /opt/allin-one` 拿回 `data/`、`.env`、compose → 起 Postgres → `pg_restore` → 起其余容器。2026-09-23 演练：临时容器 `pg_restore` 后 `content_items` 11,484、`watch_records` 1,177、alembic 0028，与生产一致。

## 6. 日志与监控

**日志**：

| 位置 | 内容 |
|---|---|
| `docker logs <容器>` | 各容器 stdout，10MB × 3 轮转 |
| `/opt/allin-one/data/logs/backend.log` | API 进程，`RotatingFileHandler` 10MB × 5 |
| `/opt/allin-one/data/logs/worker.log` | worker 进程 |
| `/opt/allin-one/data/logs/error.log` | 所有进程的 ERROR 汇总 |
| `LOG_LEVEL` | `.env`，默认 INFO |

坑：服务层或 MCP 导入 `app.tasks.procrastinate_app` 会执行 `setup_logging("worker")`，让 API / MCP 进程去写 `worker.log`；`system_health.py` 为此不导入它。

**健康判定**：

| 层 | 方式 |
|---|---|
| 进程 | `GET /health`：database / RSSHub / Browserless 三项；compose healthcheck 据此判 healthy |
| 系统总评 | MCP `get_system_health(time_range)`：采集、同步、作业、源健康一次拿到，与仪表盘同口径；`get_source_health(problems_only / source_name)` 看单源最近运行与错误文本；`get_recent_failures` |
| 页面 | 仪表盘"信息源健康"三级堆叠条、7 天失败率、需要关注 / 失败排行 |
| 源是否在采集 | `is_active AND schedule_enabled` 两个字段的与，排查必须同时看 |
| the-one `/health-check` | 脚本层：MCP 连接（`claude mcp list`）、部署 vs repo 漂移、digest 水位线年龄；Claude 层：`get_system_health` 转述、关键源白名单时效（`intel/信息源.md` Tier 1）。**未覆盖**：本系统备份心跳 `last-success` |

## 8. 已知故障与处置

| 症状 | 原因 | 处置 | 出处 |
|---|---|---|---|
| the-one 调 API 得 401 | `API_KEY` 轮换或 the-one 侧 env 丢失 | 比对 `settings.local.json` 与 `/opt/allin-one/.env`；不要先怀疑服务 | memory `env-home-server-allin-one` |
| 某 RSSHub 源连续失败 503 | 上游路由失效（LatePost、Twitter List / User 曾如此） | 看 `get_source_health(source_name)` 错误文本；停用源或换路由 | 家庭网络 07 §15 |
| 迁移报 DuplicateTable | 应用启动期 `create_all` 已建表 | `alembic stamp <rev>` 后再 upgrade | memory `project-allin-one-film-library` |
| 部署时基础镜像拉不下来 | 镜像源抽风 | 脚本自动换下一个候选；或 `REGISTRY=` 指定 | `deploy-home-server.sh` |
| 影视库列表卡死 | 曾因海报接口每次现拉 TMDb | 已改为入库落盘 + 未命中一次回填；若再现，查 `data/posters/` 是否被清 | `design_film_library.md` §2.6 |
| 日报 / 周报从未成功 | `get_llm_config()` 无 Key 时 raise，破坏降级路径 | 任务已停用；恢复前先修降级路径并改 `_RETIRED_TASKS` | memory `project-allin-one-architecture-2026-09` |
| API / MCP 进程写 `worker.log` | 导入了 `app.tasks.procrastinate_app` | 服务层不导入它 | `system_health.py` 注释 |
| 生产与仓库不一致 | 生产目录直改未回流 | `diff -rq` 两边 backend，改回仓库再部署 | memory `env-home-server-allin-one` |
| MCP 容器起不来 | `mcp` 包版本 ≥2 | requirements 已锁 `<2` | 同上 |
| 同步型源被"采集" | 调度器 / 端点对非采集型源应返回 400；曾给同步源写假成功记录（B 站 261 条） | 已由注册表在入口拦截；再现则查 `is_collectable` | `audit_2026-09_architecture.md` |

| 临时 postgres 容器 `pg_restore` 报 "shutting down" | initdb 后容器会重启一次，`pg_isready` 提前为真 | 等日志第二次 "ready to accept connections" | 2026-09-23 演练 |
| GitHub push 被 reset（端口 22） | 网络层 | `GIT_SSH_COMMAND="ssh -o Port=443 -o HostName=ssh.github.com -o HostKeyAlias=github.com" git push` | 2026-09-23 |
